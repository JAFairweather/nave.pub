nave-login — every branch, rendered once

The shared sign-in surface from nave-login.mjs. Each panel below is one real renderLogin() call with a different set of callbacks, because the component shows a control only when its callback is supplied — so the option set is the layout.

Nothing on this page signs anything. Every button reports what it would have done and stops. A demo that appeared to sign you in would be a fabricated approval on the one surface where a person is deciding whether to trust a key prompt.

Control plane — everything on

Gold accent. Extension present, remote signer, bunker paste, and the advanced local-key escape. The maximal surface.

No extension installed

The single most common first visit. hasExtension:false drops the primary button entirely, so the remote-signer path must stand on its own.

App family — extension only

Purple accent, one path, no bunker row. Themed by a single token on the mount, which is the whole theming contract.

Error state

setLoginStatus(el, msg, 'error'). A refused or failed connect has to be legible without a re-render.

Bunker only, mid-flight

No extension, no NIP-46 pairing link — just a pasted bunker://, with a live status while the signer is asked to approve.

Minimum viable card

One callback and a title. Everything optional omitted — proof the component degrades to a card rather than to a broken layout.
