# Nave — Standards

**The canonical rulebook for how the Nave ecosystem operates.** How we work, how we
manage repos, how we handle keys and boxes, how we ship. If a rule about *operating*
lives anywhere, it lives here; the domain docs (`HANDOFF.md`, `PROJECTS.md`,
`IDENTITY-REGISTRY.md`, `NOPS.md`, `SIDE-QUESTS.md`, `nave-architecture-decisions.md`)
provide the surrounding context and the deep narrative, and **point here** for the
rule itself. When a rule changes, change it here, in the same PR as the work.

> This doc is *normative* (what you must do). `INVENTORY.md`/`JOURNEY.md` are
> *descriptive* (what exists and why). `nave-architecture-decisions.md` is the
> *record of rulings* (AD-1…11) — the architecture standards live there; this doc
> references them rather than restating them.

---

## 1. Working conventions

- **Issues-first.** New work = a discrete GitHub Issue per repo, drafted for approval
  before code. Every commit is **bookended by the issue(s) it addresses** — open
  before, reference/close in the commit or PR. Check for an existing issue before
  filing; the fleet queue is real, and duplicates are worse than none.
- **PRs with the Director's explicit merge.** Code review flows through a PR that
  James merges. **Doc-only** changes may commit straight to `main` **with an issue
  reference** in the message.
- **Verify the tree, not the PR badge.** Confirm what actually landed by reading the
  merged tree, not a green checkmark. Never stack rebase-merges (see SIDE-QUESTS: the
  P-series cascade).
- **`git fetch` before asserting anything is missing.** A stale local `main` makes a
  grep of an out-of-date file "prove" something undocumented that a merged PR already
  recorded. Verify against origin, never from memory.
- **Commit trailer:** `Co-Authored-By: Claude <noreply@anthropic.com>` — plain. **No
  model identifiers** anywhere in commits, PRs, or artifacts (the trailer included).
- **PR-body footer:** end a PR description with
  `Drafted with assistance from [Claude Code](https://claude.com/claude-code)`. The
  softer wording — **not** `🤖 Generated with…` / "Generated by Claude Code," which is
  retired. (Distinct from the *post* disclosure line enforced in `post-format.mjs`.)
- **Confirm before the irreversible.** Deploying to a live box, merging to `main`, and
  other outward-facing or hard-to-undo actions get the Director's explicit go each
  time; approval in one context doesn't carry to the next. Report outcomes faithfully
  — if a step failed or was skipped, say so.

## 2. Hard constraints (never violate)

- **Never print nsecs / secrets / keys / IPs** in chat or artifacts — npubs, names,
  and roles only. Refer to boxes by role: **main · relay+bunker · warm.contact**. SSH
  IPs live in Bitwarden and local `~/.ssh`, nowhere else.
- **A bunker:// connect string pasted into a chat is BURNED** — re-mint from the
  console. Bitwarden is the vault.
- **firewalld is BANNED on Docker hosts** — it breaks Docker networking. Port control
  is the on-box `deploy/ops/firewall.sh` (nftables) + the provider edge, never
  firewalld.
- **Identity env/npub files never enter an app repo.** The ignore rules are
  pattern-based (`*.nave.env*`, `*.npub.txt`); sealed envs live with the deploy
  secrets.
- **Two Quills — never conflate them; both use the env var `QUILL_NSEC`.**
  *canonical* = `npub1jp4ay…` / `906bd25bbfc9` / `quill@nave.pub` (warm.contact
  reconnect agent); *James's* = `npub13uuznpc…` / `8f3829871ec5` / `jaf-quill@nave.pub`
  (his personal instance + drafting hand). **James's Quill's key never goes to
  Nactor** — it's a director-path (Ngage) identity; Nactor isn't its approver, the
  Director is. When unsure which is which, the short-id `8f3829871ec5` is James's.
- **Public posts never link the gated hosts** (Cockpit, Console). `luke/brief/` ships
  in a public image — nothing private goes in it.

## 3. Repo & project management

The registry of record is **`PROJECTS.md`** (repo, subdomain, status). To add a
project, **in a single PR**:

1. Mint its subdomain in `deploy/caddy/Caddyfile` (usually `import app <name>`) and
   `deploy/sites.sh`.
2. Add its row to `PROJECTS.md` (name, what it is, repo, served, status).
3. If it publishes to nostr, add its identity to `IDENTITY-REGISTRY.md` and its hex
   to the relay `deploy/relay/allowlist.json`.
4. Put the narrative/architecture context in `INVENTORY.md`.

- **Every repo is its own GitHub repo** under `JAFairweather/…`; several are checked
  out inside the `nave-spine` workspace, others directly under `~/Projects` — see the
  local-path column in `PROJECTS.md`. No per-subdomain repos.
- **Status is honest:** distinguish *shipped* from *designed* everywhere (docs, PRs,
  posts). ✅ live · 🟡 alpha · 🟢 core-live · 📄 spec · 💤 parked · 🧭 concept.

## 4. Identity & key custody

- **New agent, at birth (the checklist):** mint key → add hex to
  `deploy/relay/allowlist.json` → store nsec in **SOPS** → add a **Bitwarden** secure
  note → add a row to `IDENTITY-REGISTRY.md`. That registry is the single
  human-readable index of the whole identity graph — **npub / role / custody only,
  never an nsec** (it's a public repo).
- **Custody tiers:** **SOPS** (`deploy/secrets/nave.enc.env`, age) for the fleet agent
  nsecs; **Bunker** (Bunker46, encrypted) for `sovereign` + `operator`; **agent-held**
  runtime keys for the Buzz nest (`kerouac`/`dennis`/`mydude`) — those are *not* in
  SOPS and must not be; if lost, the identity is re-minted, no recovery path.
- **Vault-critical items go in Bitwarden:** the SOPS age key
  (`~/.config/sops/age/keys.txt` — unlocks every agent nsec), the bunker
  `ENCRYPTION_KEY`, the `nave_mgmt` SSH key + passphrase, per-box root passwords, the
  CI keys.
- **Approval happens where the signing key lives (AD-10).** Box-custodied keys →
  Nactor → its approval channel. Drafts for the Director → Ngage, gift-wrapped to his
  npub, signed in his own hand. An identity binds to exactly one approval path.

## 5. Fleet & box ops

- **New box dress code:** on the fresh box, `MGMT_PUB='…' sh deploy/ops/newbox.sh`
  (installs the mgmt key + runs `harden.sh` → `firewall.sh`); then from the Mac, with
  the provider console open as a lifeline: edge firewall to 22/80/443 → **prove key
  login** (`ssh … 'echo KEY_OK'`) → **only then** `deploy/ops/rekey.sh root@<box>
  --lock`. Order is the point: a fresh box can never lock you out.
- **Break-glass** is the provider console (out-of-band; root password in Bitwarden);
  key-only SSH never locks you out of the box itself.
- **CI:** `fleet-ops` (full) + `relay-ops` (restricted allowlist). The `ops.yml`
  custom input is `command`; runner SSH to main can time out while the box is healthy
  — retry, or use the direct mgmt path for reads. Details (by role, no IPs) in
  `NOPS.md`.
- **The three boxes** (by role): **main Nave** (Docker — nact/luke/nvoy/nactor/caddy),
  **relay+bunker** (strfry + Bunker46), **warm.contact** (native Caddy + Node).

## 6. Deploy mechanics

- **App repos do NOT self-deploy.** The box pulls each app repo via **`nave.pub`'s
  `deploy/sites.sh`** during a nave.pub deploy. To ship a change in `nact`/`nvoy`/
  `luke`/…: merge to that repo's `main`, then run the nave.pub **`deploy.yml`**
  (`gh workflow run deploy.yml`, or a push to nave.pub `main` touching `deploy/**`).
- **Docs don't deploy the box** — a push touching only `**.md` / `.github/**` /
  `deploy/ops/**` is in `deploy.yml`'s `paths-ignore`.
- **Verify with a cache-busted, new-only marker.** After a deploy, confirm the new
  code is actually served:
  `curl "https://<host>/<file>?cb=$(date +%s)" -H 'Cache-Control: no-cache' | grep -c '<new string>'`.
  A plain grep can hit a cached copy and read as "deployed" when it isn't; grep a
  string that exists **only** in the new code.

## 7. Architecture rulings

The binding design decisions are **AD-1…12** in `nave-architecture-decisions.md` —
read them there; the newest carry equal weight to the thesis: **AD-9** (voice is
evidence, per identity — real writing only, never AI-assisted output), **AD-10**
(approval happens where the signing key lives), **AD-11** (one sign-in,
promote-don't-level), **AD-12** (one agent, two planes, N slices).
**Note AD-7 appears first in that file, before AD-1** — do not scan it by position.

**The names are normative too.** `docs/architecture/06-glossary.md` is the
vocabulary of record — one line per name. Use its words; do not coin synonyms for
concepts it already covers (AD-8: *new synonyms fragment vocabulary the docs already
rely on*). If a new name is genuinely needed, it lands in the glossary and the ADR
log **in the same PR that introduces it.**

## 7a. Design system

`design/tokens.css` is the source of truth and `design/DESIGN.md` is the reference.
Both are **normative** — this section exists because they previously were not cited
anywhere, and the fleet drifted.

- **Apps vendor (inline) the system; they never fetch it and there is no npm
  package.** Every app is a no-build static client. Override only `--accent`,
  `--accent-bright`, `--accent-ink`.
- **Never re-vendor and re-selector in one commit.** Land the re-vendor with a
  transitional alias (e.g. `--panel2: var(--panel-2)`), remove the alias a deploy
  later. A token change that also moves markup is unreviewable.
- **A shared component is promoted, never forked** (AD-11). If an app needs
  different behaviour, change the shared component and re-vendor — a local edit to a
  vendored file is drift, and `bin/nave-drift` reports it as `modified locally`.
- **Vendored copies carry a hash provenance stamp**, and `design/VENDOR.json` is the
  manifest. A prose stamp goes stale silently; a hash does not.
- **Colour that encodes risk is shared like the risk spec it renders.** Nact's
  ceremony spec is shared between its runtime, its console and its signing page *so
  a signing surface can never show a softer picture than the review console* — the
  same reasoning binds the tier colours. A softer colour is a softer picture.
- **A count badge means a human decision is waiting.** Nothing else carries one.
- **Disconnected means empty** (AD-11): a control plane never renders a fabricated
  identity, approval or count as if real. Prefer an affirmative "did not answer,
  so nothing is shown — this is not the same as nothing existing" over a zero.

## 8. Voice & posting

- **Voice is evidence, per identity (AD-9).** One steering file per identity, one
  drafting pass per identity, sources are real writing only. Never learn voice from
  AI-assisted output — that's a feedback loop.
- **Drafting house rules ride every public post:** a `nave.pub` link (+ the named
  app's own link), a card graphic, real hashtags — asked of the model, **enforced
  deterministically** in `post-format.mjs`.
- **External-post voice (outside the fleet — spec forums, third-party repos):** first
  person singular, representing **James, not Nostr or any community** — his own ideas,
  expressed using the protocol. Attribution follows the disclosure rules above; never
  overclaim (shipped vs. designed).

## 9. Learn from the scars

`SIDE-QUESTS.md` is the running log of incidents and the rule that stuck from each —
**read it before touching git history, Dockerfiles, or caches.** Headline lessons:
the P-series rebase-merge cascade (→ "verify the tree, never stack rebase-merges");
the stale local `main` that made a grep lie (→ "`git fetch` first"); the two-Quills
`QUILL_NSEC` conflation (→ this doc's two-Quills rule).
